# DentVision для Android — кабинет клиники

Нативный клиент кабинета клиники (CRM) к тому же бэкенду, что и веб. Отдельный
модуль: код в `src/` и `dentvision-backend/` он не трогает и в сборку веба не
входит.

## Откуда берутся данные

Ниоткуда, кроме настоящего API. Ни одного выдуманного эндпоинта, поля или
экрана: каждый метод в `data/api/` соответствует существующему маршруту
бэкенда, каждая модель в `data/model/` списана с ответа этого маршрута и с
`src/types.ts`.

Права тоже не переизобретаются. `POST /api/auth/login` возвращает `pages`,
`permissions` и `capabilities` — приложение их сохраняет и показывает ровно то,
что разрешил сервер. Матрицы ролей на устройстве нет.

## Три сборки, и какая для чего

`BuildConfig.API_BASE_URL` задаётся в `app/build.gradle.kts`; значения адреса —
те же, что и в `src/utils/api.ts`.

| Сборка | Адрес API | Подпись | Для чего |
|---|---|---|---|
| `debug` | `http://10.0.2.2:3001` | отладочная | разработка на эмуляторе с локальным бэкендом |
| `preview` | `https://dentvision-api.onrender.com` | отладочная | **поставить себе на телефон** |
| `release` | `https://dentvision-api.onrender.com` | не задана | выпуск; подписывать настоящим ключом |

`10.0.2.2` — это `localhost` машины-хоста с точки зрения эмулятора Android; на
настоящем телефоне этот адрес не значит ничего. Поэтому для телефона нужен
именно `preview`: `debug` туда ставится, но никуда не ходит, а `release` ходит
куда надо, но неподписанный APK Android установить откажется.

Открытый (не-TLS) трафик разрешён только в `debug`: `usesCleartextTraffic`
объявлен в `app/src/debug/AndroidManifest.xml` и на другие сборки не влияет.

## Сборка

Нужен Android SDK (platform 35, build-tools 35.0.0) и JDK 17+.

```
export ANDROID_HOME=/путь/к/android-sdk
cd android
./gradlew assemblePreview
```

APK окажется в `app/build/outputs/apk/preview/app-preview.apk`.

Готовый APK можно и не собирать: его выкладывает GitHub Actions
(`.github/workflows/android.yml`) на каждое изменение в `android/` — вкладка
Actions, артефакт `dentvision-preview-apk`. Там же его можно собрать кнопкой
через «Run workflow».

## Установка на телефон

1. Скачать `app-preview.apk` на телефон.
2. Открыть его. Android спросит разрешение ставить приложения из этого
   источника — это нормально для APK мимо магазина, разрешите.
3. Нужен Android 8.0 или новее (`minSdk 26`).

Первый запрос после установки может занять до минуты: бэкенд на Render
засыпает без нагрузки, и долгая первая загрузка — это его пробуждение, а не
зависание приложения.

**Эта сборка — для своего устройства, не для раздачи.** Отладочная подпись не
годится ни для магазина, ни для установки сотрудникам: у неё общеизвестный
ключ, то есть подменить такое приложение может кто угодно.

## Что готово

- Каркас: Gradle, тема из токенов веба, транспорт, сессия, навигация, оболочка.
- Вход и выход, обновление токена на 401 с одним повтором.
- Экран «Кабинет»: клиника, роль, доступные разделы.
**18 из 19 разделов CRM:**

| Раздел | Что делает |
|---|---|
| Расписание | День, записи по времени, запись с проверкой занятости |
| Пациенты | Список, поиск, заведение карты с проверкой ИИН |
| Медкарта | Аллергии, анамнез, экстренный контакт, страховка |
| Визиты | История приёмов пациента и запись нового |
| Финансы | Касса и итоги за период, двумя вкладками |
| Прайс | Позиции, цены, себестоимость материалов |
| Склад | Остатки, приход и списание, фильтр «заканчивается» |
| Лаборатория | Заказы и их движение по статусам |
| Планы лечения | Список планов клиники с суммами |
| Документы | Список договоров и согласий |
| МКБ-10 | Поиск по справочнику |
| Акции | Что действует и до какого числа |
| Сотрудники | Состав клиники |
| Зубная карта | Формула по FDI, чтение |
| Напоминания | Кого обзвонить, отправка через WhatsApp |
| Настройки клиники | График, приём, онлайн-запись |
| Тариф | План, состояние, срок |
| Автоматизация | Список сценариев и их состояние |

Не построен один раздел — **Диалоги с пациентами**: это живая переписка с
участием ИИ, у неё своя модель тредов, согласий и квот, и делать её
наполовину значило бы показать врачу неполный разговор с пациентом.

Пункт появляется в меню только вместе с работающим экраном на настоящих
данных: пустых экранов-заглушек в приложении нет — см. `IMPLEMENTED_PAGES` в
`navigation/Destinations.kt`.

## Тесты

```
./gradlew testDebugUnitTest
```

22 теста. Проверяется то, где ошибка была бы тихой и оттого неприятной:

- **валидатор ИИН** — сверен с настоящим `src/lib/iin.ts`, ожидания получены
  его прогоном, а не придуманы;
- **разбор прав** — звёздочка суперадмина, лестница действий, устаревшие имена
  ключей: ошибка здесь просто прячет кнопки, и никто не поймёт почему;
- **список на обзвон** — окно суток, статусы, сортировка, текст сообщения:
  ошибка здесь означает, что пациенту не позвонят.

## Чего приложение не делает

Приложение не запускалось ни на эмуляторе, ни на устройстве — в этой среде их
нет. Проверена сборка и юнит-тесты, но не поведение в руках.
