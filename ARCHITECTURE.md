# DentVision Architecture

DentVision is an AI Operating System and ecosystem for the whole dental industry: Practice/CRM, Diagnostics, Medical Laboratory, Dental Laboratory, Shop/Marketplace, Academy, Jobs, Community, Analytics and Finance unified by shared identity, context, events and AI.

## Product boundary

DentVision is not clinic-first. Clinics, diagnostic centers, medical laboratories, dental laboratories, suppliers, academies, professionals, patients/buyers and other supported organizations are first-class participants according to the implemented organization/workspace and permission model.

## Runtime contract

`User → Identity → Active Context → Workspace → Role + Permissions → Data → Domain Event → AI Context → Action → Verification → Audit`

## Clinical graph

`Patient → Diagnosis → Imaging → AI Findings → Treatment Plan → Appointments → Procedures → Lab → Materials → Documents → Payments → Communication → Follow-up → Outcome`

## Ecosystem graph

`Professional / Organization ↔ Network ↔ Practice ↔ Diagnostics ↔ Laboratory ↔ Shop/Suppliers ↔ Academy ↔ Jobs ↔ Finance ↔ AI`

## Non-negotiable boundaries

- Workspace/tenant context is explicit for every data-bearing operation.
- Organization and branch scope is enforced by the backend; client IDs are never authorization proof.
- Database/domain state and event state are authoritative; LLM context is not durable business state.
- AI actions have explicit risk/permission levels: READ, SUGGEST, CONFIRM, EXECUTE, BLOCKED.
- Executable actions are auditable and idempotent where side effects matter.
- Clinical/irreversible financial mutations use the required human-confirmation policy.
- Web and Android share product contracts rather than maintaining incompatible business rules.
- Existing domain models and APIs are extended rather than duplicated.

## UX architecture

The visible product uses progressive disclosure:

`Welcome / Discovery → Intent → Auth when required → Contextual Home/Workspace → Real workflow + AI`

The ecosystem may be large internally, but the user is shown only the information and actions relevant to the current role, organization, entity and task.

## Project control plane

The machine-readable project index lives in `.dentvision/` and is regenerated by:

`npm run project:index`

Generated inventories are factual code output, not product requirements. The canonical product/system specification is `docs/DENTVISION_MASTER_SPEC.md`; Product DNA supplies constitutional quality rules, while the Execution Plan and Context govern sequencing/current state.
